6. Data Flow for Collaborator Dashboard

Flow: My Hours This Week

useMyTimesheetData(employeeId, weekStart, weekEnd)
↓
Queries: project_members, projects, clients
↓
Returns: ProjectWithMembers[] with employee role, hours_per_month
↓
Dashboard displays: Project name → Role → Planned hours → Actual hours entered

Flow: My Allocations This Month

useMyAllocationData(employeeId, monthKey)
↓
RPC: get_allocation_employee_detail() with date range
↓
Returns: planned_hours, actual_hours per project
↓
Dashboard displays: Project allocation % vs capacity, activity hours breakdown

Flow: My Tasks & Deadlines

useProjectActivities(projectId) + useCardTasks(cardId)
↓
Queries: project_activity_cards (assigned to me), project_activity_tasks (assigned to me)
↓
Returns: cards with column_name (status), tasks with due_date, completed_at
↓
Dashboard displays: Cards by status → Tasks by due date

Flow: Timesheet Submission Status

useWeekSubmission(weekStart, tenantId)
↓
Queries: timesheet_submissions + project_timesheets (is_locked)
↓
Returns: status ('draft' | 'submitted'), submitted_at, submitted_by
↓
Dashboard displays: "Week of [date]: [status]" badge with submit button

Flow: Pending Notifications

useInboxNotifications('all')
↓
Queries: notifications WHERE recipient_id = me AND is_read = false AND is_archived = false
↓
Returns: Notification[] with category, priority, title, message, action_url
↓
Dashboard displays: Notification badge (count), inbox list with filter tabs

7. Business Rules & Terminology

.harness/domain-glossary.md

Key Concepts:

Colaborador/Employee: Person internal to org, allocable to projects, with costs & benefits
Timesheet: Hour allocation by activity/project/period. Apontamento de horas.
Activity Type: Category used in hour logs (e.g., "Development", "Testing", "Design")
Projeto: Delivery contract with members, revenues, installments, milestones, status
Alocação: Assignment of employee hours to project/activity for period (planned vs actual)
Tenant: Isolated data unit in system (multi-tenant architecture with RLS)

9. Key Considerations for Smart Dashboard

✅ Available Data:

  • Hourly Data: Actual hours logged by activity, weekly submissions, planned allocations
  • Projects: Full project metadata, dates, status, members, manager
  • Tasks: Activity cards, tasks, sprint membership, due dates, completion status
  • Notifications: System-wide alert infrastructure with categories and priority
  • Capacity: RPC functions for calculating employee capacity by date range
  • Personal Items: Personal kanban board for individual tasks

🎯 Smart Dashboard Features Possible:

  • 📊 Allocation Summary: Planned vs actual hours for current month with capacity utilization %
  • 📝 Weekly Timesheet Widget: Quick entry/submit for current week
  • ✅ My Tasks: Cards assigned to me with status and due dates (from project_activity_cards + tasks)
  • 🔔 Alerts & Reminders: Pending timesheet submissions, task deadlines, blocked cards
  • 📈 Quick Stats: Total hours this week, projects assigned, pending tasks count
  • 🎯 Personal Kanban: Integration with personal to-do board
  • 💼 Project Overview: List of active projects with progress % and next milestone
  • ⚠️ Over-allocation Alert: When allocated hours exceed capacity

🔧 Technical Patterns:

  • All data fetching uses @tanstack/react-query with queryKey invalidation
  • Multi-tenant isolation via RLS (Row Level Security) - automatic tenant_id filtering
  • RPC functions for aggregated data (allocation summary, capacity calculation)
  • Supabase real-time subscriptions available for live updates
  • Auth context (useAuth) provides current employee data
